# React 静态 Demo 设计系统 Review

生成日期：2026-05-08

本文件沉淀当前“健康服务数据治理与运营分析展示台”的视觉与可读性约束。它只服务于 React 静态 Demo 的视觉 polish，不改变页面结构、数据字段、指标口径、安全边界或部署路线。

## 品牌气质

- 专业。
- 克制。
- 可信。
- 健康服务。
- 数据治理。
- 运营分析。
- 适合需求方截图汇报。

界面应像一个健康服务数据治理产品，而不是营销网站、炫光大屏或诊疗能力展示页。

## 禁止风格

- 医疗 AI 化。
- 营销页化。
- 炫光大屏化。
- 过度渐变。
- 过度动画。
- 装饰性大图压过数据内容。
- 空洞口号替代真实指标。

## 色彩规则

- 主色：深绿，用于导航高亮、KPI 强调、流程编号和关键状态。
- 背景：浅灰绿，降低医疗科技感和大屏感。
- 卡片：白色，承载 KPI、图表、表格和安全说明。
- 边框：低饱和灰绿，保持信息分组但不抢视觉。
- 状态色：
  - 存在：绿色浅底。
  - 无标记：灰色浅底。
  - 已取消：琥珀浅底。
  - 禁止字段：低饱和红色浅底，仅用于风险提示。

## 字体规则

- H1 / 页面主标题：`text-2xl` 至 `text-3xl`，用于页面价值表达。
- 区块标题：约 `text-xl`，用于运营分析分组等页面区块。
- 卡片标题：约 `text-base`，保持紧凑且可扫读。
- 正文：`text-sm` 至 `text-base`，强调行高和可读性。
- 说明文字：`text-xs` 至 `text-sm`，用于口径、边界和脚注。
- KPI 数字：`text-3xl`，突出但不做大屏数字墙。

不使用负字距，不使用夸张 display 字体，不牺牲中文可读性。

## 组件规则

### KPI Card

- 结构固定为：指标名称 / 大数字 / 口径解释。
- 不把 flags 或记录数解释为支付状态、诊疗结果或客户数。
- 卡片高度保持一致，便于首屏截图。

### Chart Card

- 标题说明维度。
- 描述说明当前口径。
- 脚注统一为“按服务记录统计，不代表医疗结论。”
- 横向柱状图左侧标签要优先保证可读性。
- 图例和轴标签使用克制字号，避免拥挤。

### Table Card

- 明确提示表格字段来自静态 JSON 合同。
- 移动端提示可横向滑动查看完整字段。
- 表格保留搜索、筛选、排序、分页和详情抽屉。
- chips 使用统一状态样式。

### Drawer

- 标题突出记录 ID 和服务类型。
- 只展示允许字段和 flags。
- 不展示任何敏感原文。
- 说明文字保持克制，强调 flags 只是存在性。

### Security Card

- 禁止字段按身份识别类、医疗原文类、支付与备注原文类分组。
- 安全流程表达为：本地 CSV / 安全导出 → allowlist 生成 JSON → 敏感字段检查 → React 只读展示。
- 不夸大当前 Demo 能力。

## 本轮 Polish 摘要

- 首页主标题改为更面向需求方的价值表达。
- 首页增加“可查询 · 可统计 · 可演示 · 可扩展”价值条。
- KPI 卡片结构和口径说明更统一。
- 运营分析页增加“服务结构”和“运营资源”分组。
- 图表卡片增加统一口径脚注。
- 服务记录页强化 JSON 合同说明和移动端横向滑动提示。
- 服务状态、flags 采用统一 chips。
- 详情抽屉标题突出记录 ID 和服务类型。
- 数据安全页按风险类型分组禁止字段，并增加安全展示流程。
