# 视觉设计方向

## 总原则

React 静态 Demo 的视觉目标是：专业、克制、可信、数据产品感。

它面向需求方演示和截图汇报，重点是让人快速理解数据治理链路、运营指标、服务记录检索和安全边界，而不是制造营销冲击力。

## 应该呈现的气质

- 像一个健康服务数据治理产品。
- 像一个可继续产品化的运营分析展示台。
- 信息密度适中，适合快速扫读。
- 图表、表格、KPI 和说明文字层级清晰。
- 截图后仍能看清页面主题、核心数据和安全声明。
- 移动端至少支持基本阅读和浏览。

## 不做的方向

- 不做医疗 AI 官网。
- 不做营销页。
- 不做炫光大屏。
- 不做夸张渐变。
- 不做过度动画。
- 不做装饰性大图主导页面。
- 不做空洞口号堆叠。
- 不做暗示诊断、治疗建议或临床能力的视觉表达。

## 组件方向

- shadcn/ui 只作为基础组件库，不决定信息架构。
- ECharts 用于图表表达，图表标题和 tooltip 必须保持“服务记录统计”口径。
- TanStack Table 用于服务记录表格，重点保证搜索、筛选、排序、分页和详情查看可用。
- lucide-react 用于导航、状态、工具按钮等图标，不应替代必要文本标签。

## 页面布局

- 总览页以治理链路、核心 KPI、模块分工、Demo 边界为主。
- 运营分析页以图表网格为主，避免大屏化和过度装饰。
- 服务记录页以高可读表格为主，详情抽屉突出允许字段和 flags。
- 数据安全与后续路线页以规则、边界和路线说明为主，使用清晰分组。

## 色彩与字体

- 色彩应偏中性、专业、可信，可使用少量蓝、青、绿作为数据和状态强调。
- 避免单一蓝紫渐变统治页面。
- 避免大面积荧光色、霓虹色和高饱和医疗科技感。
- 字体优先考虑清晰、稳定、易读；不要为了“高级感”牺牲中文可读性。

## 图表可读性

- 图表必须有明确标题。
- 图例、轴标签、tooltip 文案不得夸大口径。
- Top 10 图表应显示“待确认”分类，不隐藏空值归一化结果。
- 空图表需要有解释性空状态，不能显示空白或报错。

## 动效

- 仅使用帮助理解层级和状态的轻量动效。
- 不使用大面积入场动画、连续背景动画或干扰表格阅读的动效。
- 演示截图场景下页面应保持稳定。

## 外部设计 skill 的角色

外部成熟前端/设计 skills 只能用于纯视觉设计审查和 UI polish，例如：

- 视觉层级。
- typography。
- spacing。
- card layout。
- chart readability。
- mobile responsiveness。
- AI 模板感。
- 是否过度营销化。

外部 skill 不能决定产品结构、页面范围、数据字段、指标口径、安全边界或部署架构。
